  1. 01动态问答内核（从 0 到 1）

    • 问题获取与答案保存从 0 到 1 主导 C 端核心问题接口和问答主链路。围绕页面、问题、选项、答案、阶段和版本建立模型，完成问题获取、答案保存、页面导航和中断恢复，并将问答结果与业务数据联动。
    • 多端、多机构复用持续将页面级接口演进为基于 CEL 表达式的动态问答体系。C 端和 B 端复用同一套内核，各家贷款机构（Lender）可以配置自己的问卷规则，并行使用不同问卷版本。

  2. 02复杂规则与数据一致性

    • 本次答案优先计算下一页时，先用本次请求中的答案覆盖已保存的答案，再执行跳页规则。即使新答案尚未落库，返回的下一页也能反映用户刚作出的选择。
    • 回退后的数据清理用户回到前页修改答案时，清理因改走新路径而失效的数据，再将有效答案映射到相关业务对象，避免旧路径的答案继续参与报价或提单。
    • 历史申请的版本绑定将 Application 与问卷版本绑定，并按 Lender 和版本隔离规则。问卷升级后，已发起的申请仍按原版本继续办理。

  3. 03B/C 端核心业务交付

    • 业务模块主导 Customer Portal、Pipeline、Quotes 和 Application Centre 的交付，并负责 Documents 文档中心的核心建设。

    • 前后端交付以 Java 后端为主，借助 AI 完成 React 页面开发及接口契约。我负责生成代码的审查与修正、前后端联调、测试和最终交付。

  4. 04多家金融机构与外部服务接入

  5. 05Lender Portal 自动化提单

    • 后端与浏览器协作针对缺少标准 API 的机构，主导后端与 Playwright Worker 的架构设计和核心流程开发。后端以任务状态机跟踪进度，Worker 在机构门户执行操作，通过带 HMAC 签名的回调同步任务结果。
    • 不可逆提交通过 Dry Run 试运行验证流程，在需要时引入一次性验证码（OTP）和人工确认，用 Watchdog 监控任务超时。遇到无法确认是否已提交的情况，将任务转交人工核查，避免重复提单。

  6. 06外部雇主数据目录建设

    • 采集与标准化负责 SMART、MAXXIA 两个来源的雇主数据采集和同步。解析外部数据、统一字段格式，并在写入前校验记录总数及相对上批的降幅。
    • 更新、回滚与缓存在事务内通过 Upsert 新增或更新雇主记录，并将失效记录标记为 inactive。同步失败时回滚，保留上一批有效数据。更新成功后使相关缓存失效，让业务能读到最新的可用目录。

      采用令牌桶算法，结合 Guava Cache、Guava RateLimiter、自定义注解和 AOP 切面实现接口级限流。在类或方法上添加注解并配置参数，即可控制相应接口的请求速率。

    6. 直播加速订单服务
